# GymOS Backend: API Handoff

This document asserts the structural expectations generated by the frontend Phase 20 contracts and DOC-006 limitations.

## API Foundation
- **Base API Path**: `/api/v1`

## Authentication
- **Flow**: User logs in with `email`/`password` at `/api/v1/auth/login`.
- **Retrieval**: System responds with an `{ access, refresh }` JWT set.
- **Usage**: Token passed securely using Authorization Header (`Authorization: Bearer <token>`).
- **Rotation**: A request to `/api/v1/auth/refresh` rotates the active token using the `refresh` key.
- **Logout**: Clears and revokes the active payload.

## Response Envelope
Every endpoint MUST route nested structure payloads mirroring DOC-006 exactly.
- **SUCCESS**:
```json
{
  "success": true,
  "data": { ... },
  "message": "Resource processed cleanly"
}
```
- **ERROR**:
```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Human readable context",
    "details": { ... }
  }
}
```

## Pagination
API responses for arrays must be nested utilizing Django REST Framework page limitations:
`/api/v1/members?page=1&page_size=20`
```json
{
  "success": true,
  "data": {
    "count": 140,
    "next": "http://api/v1/members?page=2",
    "previous": null,
    "results": [ ... ]
  }
}
```

## Important Verified Contracts
*Do not alter these paths, as they have been rigorously normalized into Phase 20 E2E assertions.*
- **Notifications**: `POST /api/v1/notifications/{id}/read`
- **Gym/Tenant administration**: 
  - `GET /api/v1/gyms`
  - `GET /api/v1/gyms/{id}`
  - `PATCH /api/v1/gyms/{id}`
  - `POST /api/v1/gyms/{id}/suspend`

⚠️ *Warning*: Do not confuse Frontend SPA application navigation routes (e.g. `/admin/tenants`) with API endpoint URLs (`/api/v1/gyms`). The SPA utilizes Axios to resolve the API route.
